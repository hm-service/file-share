为什么是 Shelf

忽略现有实现后重新想一遍文件库。

  1. 内容优先，工具退后。没有固定侧栏。大标题、留白和分隔线先建立阅读节奏，文件本身才是主角。
  2. 收藏不是分类，而是“置顶”。把收藏做成首屏三张横向卡片，比在列表里插一个收藏区更符合“常用”的心智。
  3. 上传变成常驻的 compose bar。像发消息一样上传：不进入独立页面、不弹 modal，队列只在底部轻轻展开。
  4. 全局拖放，而不是指定热区。拖到页面任何位置都出现整页落点，减少瞄准成本；拖到分组标签则直接归类。
  5. 行是安静的，操作是按需的。列表只保留文件名、类型与元数据；操作在 hover / 聚焦时出现，手机端点行进入底部详情。
  6. 同一套结构适配两种设备。桌面是“书架 + 常驻上传条”，手机是“单列 + 底部详情”，共用同一份 DOM 与断点。
